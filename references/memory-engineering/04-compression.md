# 04 压缩与摘要

## 4.1 层级摘要（最实用的压缩方案）

```
Level 0  raw（原始会话）
Level 1  session summary
Level 2  daily
Level 3  weekly
Level 4  monthly
```

ANDM 改造（§10.4）：**聚合轴从日历时间改为代码模块**——同模块的 session 摘要与 review 结论跨会话归并为「模块级经验条目」。按时间聚合在研发场景只适合做周报副产品。

## 4.2 压缩方式权衡表

| 方式 | 压缩比 | 信息损失 | 适用 |
|---|---|---|---|
| 提取式摘要 | 5:1 | 低 | 短期、关键信息保真 |
| 生成式摘要 | 20:1 | 中 | **主力方案** |
| 结构化提取 | 50:1 | 可控 | 需要结构化查询的场景 |
| token 级压缩（LLMLingua 类） | 高 | **精度风险** | 不适合承载必须逐字准确的内容 |

ANDM 策略（§10.3）：**混合式**——关键信息（决策、结论、TODO）用提取式保真，上下文叙述用生成式压缩。review 结论这类内容禁用 token 级压缩。

## 4.3 记忆蒸馏

多条具体记忆 → 一条结构化规则（Voyager 方式：技能以可执行形式沉淀，入库前自我验证）。

ANDM 对应（§10.4）：同一模块反复出现的 review 意见（如「这个模块禁止直接改全局状态」出现 N 次）蒸馏为一条模块级规约条目，而不是存 N 条相似条目。

## 4.4 原文保留锚点

摘要不可逆。每条提炼条目必须保留指向原始记录（Level 0）的链接——审核人需要能回溯原文才能判断提炼是否有损。

ANDM 对应：§4 schema 的 `evidence` 字段（source_session / commit_sha / review_ref）即此锚点。
