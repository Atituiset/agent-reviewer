# 01 记忆架构与分层

## 1.1 统一存储 + 类型标记

结论：**逻辑分离、物理可合并**。不同种类的记忆（情景/语义/程序性）不必分库——统一存储，用 `memory_type` 字段区分，不同层使用不同的索引和检索策略。

ANDM 对应：§4 的单表 schema + `kind` 字段。确定性召回走结构化过滤（模块 glob），语义召回走向量索引——同一存储、两种索引。

## 1.2 条目的生命周期元数据（程序性记忆的 Skill 结构）

Skill 类条目应携带三个可编程字段：

- `preconditions`（适用守卫）：**必须写成可编程检查**（如 glob 匹配路径），避免含糊的自然语言，否则无法机械判定适用性
- `success_rate`（学习信号）：依赖「执行 → 验证 → 回写」闭环；成功率下降 ⇒ 环境变化或技能退化，触发重学/降级/淘汰
- `last_used`（生命周期元数据）：支撑 LRU 淘汰与冷启动重验证

ANDM 对应：§10.2 的 `applies_to`（可编程守卫）、hit/miss 埋点计数、`last_accessed_at`。

## 1.3 写入器与巩固器分离

生产级记忆系统的两个异步角色：

- **Memory Writer**：写入时做重要性评分、去重，写入各 store
- **Consolidation Worker**：定期异步做摘要、去重、升级

ANDM 对应：Distiller（提炼管线）与 Governance Engine（审核/合并/升级管线）分离；quarantine 队列天然是两者之间的缓冲带（§10.1）。

## 1.4 保护优先级三级制

信任分层的通用原则：**显式陈述 > 确认过的推断 > 纯推断**。

ANDM 映射：人工 review 通过的条目 > 人工确认过的 agent 提炼 > 纯 agent 自动提炼。低信任条目可被自动降级；高信任条目只能由人删除（§10.4 pinned 保护）。

## 1.5 透明存储的取舍

有实践选择 Markdown 文件而非向量数据库存储记忆：牺牲检索效率，换取透明性和 LLM/人的可操作性。

ANDM 参考：团队记忆需要人审，**可评审性（diff 化、git 化管理）比检索效率重要**——可考虑条目主体存 Markdown 进 git 仓库，向量索引只是派生物。

## 1.6 三阶段定位

「存储 → 反思 → 经验」框架：停在「存储」阶段的记忆系统不增值；加「反思」（整理）与「经验」（提炼技能）才真正增值。

ANDM 映射：session 摘要 = 存储层；审核入库的条目 = 反思层；跨多条目归纳出的团队规范/惯例 = 经验层。三层应有独立的数据形态。
