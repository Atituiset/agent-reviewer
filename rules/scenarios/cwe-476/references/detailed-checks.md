# CWE-476 空指针解引用 评审清单

逐处检查 diff 中每个解引用点（`->`、`.*`、`*p`、`[]` 迭代器、Java 的 `.` 调用），回答以下问题：

## 1. 来源可信吗

- 指针来自函数返回值：该函数契约是否可能返回 NULL / nullptr / null？（`malloc`、`calloc`、`realloc`、`fopen`、`find_*`、查表类 API 是高危来源）
- 指针来自参数：本函数是否处于允许 NULL 传参的调用契约中？
- 指针来自共享状态/全局变量：是否存在被其他线程或析构路径置空的窗口？

## 2. 校验覆盖吗

- 解引用前是否有判空？判空与解引用之间是否可能被改写（TOCTOU）？
- `realloc` 失败路径：原指针是否被直接覆盖导致丢失（`p = realloc(p, n)` 反模式）？
- 错误处理分支、goto/异常路径、提前 return 路径上是否同样判空？（缺陷最常藏在非主流路径）
- 智能指针：`std::move` 之后的源指针是否又被使用？`weak_ptr::lock()` 结果是否判空？

## 3. 容器与迭代器

- `map[key]`、`vector[i]` 的键/下标存在性是否确认？
- 迭代器失效（erase/insert/扩容）后是否继续解引用？

## 输出要求

仅报告**能在代码中定位到具体缺失校验**的解引用点；纯推测性风险（"理论上可能为 NULL"但契约明确非空）不报告。每条 finding 给出 `file:line`、解引用表达式、缺失的校验位置。
