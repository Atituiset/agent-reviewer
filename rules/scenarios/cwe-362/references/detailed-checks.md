# CWE-362 竞争条件 评审清单

## 1. 共享数据的每个访问路径

- diff 引入或修改的共享变量（全局、静态、成员被多线程触达）：**所有**读写路径是否都持同一把锁？新增了一条未持锁的访问路径是最常见引入方式
- 读多写少场景：读路径是否也需要保护（脏读、读到撕裂状态）？
- 单标志位 + 数据的模式：标志与数据之间是否有内存序保证（atomic/fence），还是依赖了恰好成立的时序？

## 2. 锁的正确性

- 锁顺序：diff 是否引入新的加锁路径导致锁顺序反转（A→B 与 B→A 并存 = 死锁风险，联动 deadlock 场景）？
- 锁粒度：锁内是否调用了可能重入同一把锁的函数（回调、虚函数、未知下游）？
- 异常/提前返回路径上锁是否一定释放（RAII 与否）？

## 3. TOCTOU 窗口

- 「检查 → 行动」序列：检查条件与行动之间状态可被改变？（`if (p) p->op()` 的 p 可被置空；文件存在性检查后打开）
- 单例/懒初始化：双重检查锁定的读写两侧是否都是 atomic/带 fence？

## 4. 假安全

- 对不可变快照操作但快照本身是浅拷贝？
- 用了线程安全容器但组合操作（check-then-act）不是原子的？

## 输出要求

竞争 finding 必须给出**两个可交错执行的执行路径**（各含 `file:line`）及交错后产生的错误状态。仅指出"这里有共享变量"而无交错路径的不报。
