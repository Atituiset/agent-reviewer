# CWE-416 释放后使用 评审清单

## 1. 释放点之后的使用

- `free`/`delete` 之后指针是否置 NULL？未置空时，后续代码（尤其错误处理路径）是否可能再次使用？
- 同一指针在多个分支分别释放后，汇合路径上是否仍被解引用？
- `delete this` 之后是否还访问成员（包括隐式的析构链）？

## 2. 悬垂引用

- 返回/保存了局部变量的指针或引用？
- 指向容器元素的指针/引用/迭代器，在容器 `erase`/`clear`/扩容后是否仍被使用？
- `std::string::c_str()` 的指针在原 string 被修改/销毁后是否仍被持有？
- lambda 按引用捕获了即将离开作用域的变量，且 lambda 会异步/延迟执行？

## 3. 生命周期错配

- 注册回调/定时器/观察者时传入 `this` 或内部指针：对象销毁时是否反注册？diff 改了注册逻辑但未改对应的反注册？
- 跨线程移交指针：生产者释放与消费者读取之间是否有同步保证？
- 父对象销毁导致子对象持有的父指针悬垂（父子生命周期反转）？

## 输出要求

UAF 报告需给出完整的「释放点 → 使用点」路径描述（两处 `file:line`），仅说"可能悬垂"而无路径的不报。与 double free（cwe-415）同时存在时分开报告。
