# 通用评审基线清单

## 1. 正确性

- diff 是否实现了它声称的意图？边界条件（空输入、0、最大值、并发首末次）是否处理？
- 逻辑取反、条件组合（`&&`/`||` 优先级）、比较运算符（`=` vs `==`、`<` vs `<=`）是否有误？
- 修改是否与既有不变量冲突（相邻代码依赖的假设）？

## 2. 错误处理

- 新增的错误码/异常是否被吞掉（空 catch、忽略返回值）？
- 错误信息是否泄露敏感信息（内部路径、密钥、堆栈给外部调用者）？
- 部分失败状态是否可恢复，还是留下不一致的中间态？

## 3. 变更面

- 公开 API/接口/配置格式是否变化？调用方、文档、测试是否同步？
- 是否有死代码被引入（写了但无任何路径可达）？
- 日志关键点（错误路径、状态迁移）是否有足够可观测性？

## 4. 明确不报告（防 review theater）

- 纯风格偏好（命名、排版）——交给 formatter/linter
- "可以更简洁"类无缺陷的主观建议
- 无法定位到 `file:line` 的泛泛担忧
