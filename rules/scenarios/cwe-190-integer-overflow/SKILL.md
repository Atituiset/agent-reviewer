# CWE-190 整数溢出 评审清单

## 1. 溢出后流向哪里

整数溢出本身不一定有害，**流向**决定严重度。重点追踪溢出路走到：

- **内存分配大小**：`malloc(n * size)`、`new T[n]` 的乘法/加法是否可回绕成极小值 → 分配小缓冲写入大数据（联动 cwe-787）
- **边界比较**：`if (len + hdr < max)` 中 `len + hdr` 回绕成负数/小值绕过检查
- **数组索引/循环计数**：回绕后变成合法下标但语义错误
- **截断**：`int64 → int32`、`size_t → int` 强转，大值截断后符号/大小异常

## 2. 来源与类型

- 参与运算的值是否外部可控（协议长度字段、文件头、计数）？
- 有符号/无符号混用：比较运算中负数被解释成大正数？
- 运算发生在大类型还是溢出后才提升？（`(size_t)a * b` 与 `a * b` 的溢出点不同）

## 3. 防护习惯

- 加法/乘法前是否有上界校验（`if (n > SIZE_MAX / size)`）？
- 是否可用安全整数库/内建（`__builtin_add_overflow`、饱和运算）替代手写检查？

## 输出要求

报告需给出：运算点 `file:line`、可触发溢出的取值来源、溢出后的具体危害路径（分配/比较/索引之一）。无危害路径的"理论可溢出"不报。
