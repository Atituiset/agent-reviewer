第 0 阶段

一次性安装：两个动作，u-boot 侧完成

放一个 caller 文件，配三个密钥/变量——评审逻辑一行都不用写。

STEP 1 · 放 caller

.github/workflows/ai-review.yml（全部 10 行）

name: ai-review
on:
  pull_request: [opened, synchronize]
permissions:
  contents: read
  security-events: write
  id-token: write
  pull-requests: write
jobs:
  review:
    uses: <org>/agent-reviewer/.github/workflows/ai-review-reusable.yml@mvp
    secrets: inherit
STEP 2 · 配密钥

Settings → Secrets and variables → Actions

  • SecretAI_REVIEW_API_KEY = DeepSeek key
  • VariableAI_REVIEW_BASE_URL = https://api.deepseek.com/anthropic
  • VariableAI_REVIEW_MODEL = deepseek-v4-flash
至此 Actions 列表出现 ai-review 并 active——u-boot 仓里没有一行评审逻辑，这是继承的全部安装成本。
主时间线

从 PR 到告警：四个阶段

每次开 PR 或推新 commit，下面这条链路完整跑一遍。向下滚动，节点逐个点亮。

①
PR 触发u-boot 上下文

开 PR 或推新 commit → GitHub 在 PR 分支发现 ai-review.yml 的 on: pull_request: [opened, synchronize] 匹配 → 在 u-boot 上下文排队 run（u-boot 的 runner、代码、secrets）。

②
继承解析（uses 的瞬间）三件事
1 下载 reusable 全文

从 agent-reviewer@mvp 下载 ai-review-reusable.yml 全文。

2 权限校验

reusable 声明的权限必须是 caller permissions 子集（否则 startup_failure）。

3 内联执行 + secrets 透传

内联执行 + secrets: inherit 透传 DeepSeek 配置（secrets.AI_REVIEW_API_KEY / vars.AI_REVIEW_* 在被调方可见）。

类比 caller = 一行函数调用 review()；reusable = 函数体；secrets: inherit = 传参。函数体更新，所有调用方自动用新逻辑。
③
runner 逐步执行10 步 · 每步标「谁在读什么」
01 checkout 被审代码GitHub 读 u-boot

actions/checkout@v4 默认拉调用者仓 = u-boot PR 代码 → $GITHUB_WORKSPACE。

02 checkout 评审工具GitHub 读 agent-reviewer

repository: agent-reviewer, ref: mvp, path: .reviewer → 场景库 + 脚本。至此 runner 上两份代码：u-boot 的（被审）+ agent-reviewer 的（工具）。

03 豁免判定脚本读 diff 与配置

diff <20 行或纯文档跳过；读 .ai-review-mode 定模式（1/2/3）。

04 打包脚本读 git 历史

git diff base...HEAD > /tmp/pr.diff

05 codegraph 索引（模式≥2）codegraph 读 u-boot 源码

npm i -g → init → sync → .codegraph/codegraph.db（u-boot 级 ~500MB，秒级；run 结束销毁，每 PR 重建）。

06 navmap 产物（仅模式 3）GitHub 读产物分支

checkout ref: navmap-outputs → .navmap-out/（另一条 navmap-nightly workflow 预计算的产物，PR 只消费不计算）。

07 组装 prompt脚本按模式拼接

基础指令 + codegraph 判空链回溯纪律（模式≥2）+ navmap 表使用条款（模式3）。

08 claude-code-actionagent 读 diff / 场景 / 图库

约 20 轮 agent 循环后写出评审工件。

展开：action 内部发生了什么
  1. 下载 action → 装 Claude Code CLI
  2. 注入 env（ANTHROPIC_BASE_URL=DeepSeek 端点 / AUTH_TOKEN=DeepSeek key / MODEL）+ github_token + allowedTools
  3. 读 pr.diff → scenarios-for 场景路由（确定性，模型不参与）
  4. 读命中场景 SKILL.md → codegraph callers 判空链回溯（≤10 跳）
  5. Write .review/review-artifact.json
09 重新 checkout agent-reviewerGitHub 读 agent-reviewer

action 会重置 workspace，.reviewer 可能被清。

10 SARIF 转换 + 上传脚本读工件与源码

artifact-to-sarif.sh → /tmp/review.sarif（工件 + 场景 frontmatter + u-boot 源码（region.snippet + message 函数体））；upload-artifact 归档轨迹；upload-sarif → code scanning。

深水区

三个容易踩坑的机制

secrets 怎么流转、token 走哪条路径、runner 磁盘上到底有什么。

卡 A · SECRETS

secrets 怎么被读到

配置侧→ 传递侧→ 使用侧

配置侧：u-boot Settings 加密存储，yaml 永不见明文。

传递侧：secrets: inherit 全量透传。

使用侧两种注入：env:（给 Claude Code 进程，日志自动打码 ***）vs with:（给 action 逻辑）。

vars.* 明文 vs secrets.* 打码；secrets.GITHUB_TOKEN 是特例——GitHub 自动签发的 run 级临时 token，无需配置。

卡 B · TOKEN 路径

OIDC vs GITHUB_TOKEN

路径 A · action 默认

OIDC token（需 id-token: write）→ Anthropic 交换端点 → Claude App 安装 token → 评论署名 claude[bot]；前提 u-boot 装了 Claude GitHub App（我们没装 → 401）。

路径 B · 我们选的

github_token: ${{ secrets.GITHUB_TOKEN }} → 跳过 OIDC/App 交换 → runner 自带 token → 署名 github-actions[bot]；更简单、不依赖第三方 App、权限由 workflow permissions 决定。

卡 C · RUNNER 磁盘

runner 文件系统

$GITHUB_WORKSPACE/
├── .codegraph/codegraph.db   # codegraph 现场建的图库（一次性，run 结束销毁）
├── .reviewer/                # agent-reviewer checkout（可能被 action 重置）
├── .navmap-out/              # 模式3 navmap-outputs checkout
└── .review/review-artifact.json
/tmp/
├── pr.diff
└── review.sarif

时序硬约束——codegraph sync 必须在评审前完成，否则链回溯拿旧图；reviewer 把 codegraph 当普通 Bash CLI 工具用（非 MCP）。

生产端

navmap-nightly：产物从哪来

模式 3 消费的 navmap 产物由一条独立的夜间 workflow 预计算，PR 链路只读分支。

CRON

定时触发

UTC 18:17 = 北京 02:17，schedule 只在默认分支生效；60 天不活动 GitHub 自动禁用，需手动 re-enable 或改外部调度。

STEP ①

checkout master

fetch-depth: 0，增量要 git 历史。

STEP ②

生成 compile_commands.json

cmake 一行；真实核心仓复用生产 clangd 编译数据库。

STEP ③

checkout navmap 工具仓 + pip 安装

工具与数据分离，工具仓独立演进。

STEP ④

分支提取

已有产物 → navmap refresh（git diff ∩ 候选，分钟级）/ 首跑 → navmap extract（粗筛→候选→libclang 解析，十几分钟级）；产物 = 分发表/注册式/状态机表/全局变量读写清单，JSON+md 双格式标基线 commit。

STEP ⑤

navmap report 质检

ERROR / WARN / INFO 分级。

STEP ⑥

提交产物分支

git checkout -B navmap-outputs && 提交强推产物分支。

成本形态决定拓扑：codegraph 语法级秒级 → 进 PR 链路现算；navmap 语义级分钟级 → 只能离线预计算 + 分支存储 + PR 消费，时延零增加。
